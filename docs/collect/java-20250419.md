## 分库分表 sharding-jdbc(2020年止已经不更新)

```markdown
连接数-分库（提升吞吐量）
容量-分表（提升查询性能）

1000～2000万 用

分库分表：水平、垂直

数据库的垂直拆分：按功能模块来拆分

表的垂直拆分：按功能性来细化，比如价格、订单，各拆出一个表，再单独地去运算价格，性能会更好

数据库的水平拆分：水平地复制几分出来，数据表都保持一致，主要是为了提高数据库的吞吐量，数据库层面采用集群部署，涉及到数据同步的问题

表的水平拆分：水平地进行复制，复制的是表的结构，数据并不会水平复制，而是按范围或其他维度来批量地进行存储，
以达到降低单表的数据量，提升查询性能；表分布在不同的数据库当中，就叫做水平分库分表；
按取模算法、范围限定算法（数据范围、时间范围、地域范围）等

水平分库分表：表分布在不同的数据库当中

拆完后的问题：分页/排序/跨节点联合查询；事物一致性；全局唯一的主键；

数据分片

数据节点

拆完又分为逻辑表、物理表：应用层用的就是逻辑表，查的就是物理表


```

# 配置分片规则 - 用户表 # 配置世纪分片节点：ds0.course_1,ds0.course_2,ds0.course_1,ds1.course_2

spring.shardingsphere.rules.sharding.tables.user.actual-data-nodes=ds$->{0..1}.user
spring.shardingsphere.rules.sharding.tables.user.table-strategy.standard.sharding-column=user_id
spring.shardingsphere.rules.sharding.tables.user.table-strategy.standard.sharding-algorithm-name=user-inline
spring.shardingsphere.rules.sharding.tables.user.key-generate-strategy.column=user_id
spring.shardingsphere.rules.sharding.tables.user.key-generate-strategy.key-generator-name=snowflake

# 配置分片算法 # .type=MOD 取模算法 # .props.sharding-count=2 # INLINE 表示通过groovy表达式来分片算法
spring.shardingsphere.rules.sharding.sharding-algorithms.user-inline.type=INLINE
spring.shardingsphere.rules.sharding.sharding-algorithms.user-inline.props.algorithm-expression=user_$->{user_id % 2}

# 配置主键生成器 # 分布式算法配置
spring.shardingsphere.rules.sharding.key-generators.snowflake.type=SNOWFLAKE

```yaml
spring:
  shardingsphere:
    datasource:
      names: ds0,ds1
      ds0:
        type: com.alibaba.druid.pool.DruidDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/db0?serverTimezone=UTC
        username: root
        password: root
      ds1:
        type: com.alibaba.druid.pool.DruidDataSource
        driver-class-name: com.mysql.cj.jdbc.Driver
        jdbc-url: jdbc:mysql://localhost:3306/db1?serverTimezone=UTC
        username: root
        password: root
    rules:
      sharding:
        tables:
          user:
            actual-data-nodes: ds$->{0..1}.user
            table-strategy:
              standard:
                sharding-column: user_id
                sharding-algorithm-name: user-inline
            key-generate-strategy:
              column: user_id
              key-generator-name: snowflake
        sharding-algorithms:
          user-inline:
            type: INLINE
            props:
              algorithm-expression: user_$->{user_id % 2}
        key-generators:
          snowflake:
            type: SNOWFLAKE
    props:
      sql-show: true
```
